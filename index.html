PostgreSQL
표준 SQL과 트랜잭션, 제약 조건을 활용해 데이터 무결성을 지키는 스키마를 설계합니다. JSON 타입 등 PostgreSQL의 확장 기능을 이해하고 활용합니다.
GitHub
프로젝트마다 원격 저장소를 만들어 관리하고, README에 기능·실행 방법·화면을 정리해 둡니다. Issue와 Pull Request로 작업 단위를 나눠 진행 상황을 남깁니다.
Fork
팀·오픈소스 저장소는 Fork 후 upstream을 remote로 등록해 fetch·rebase로 최신 상태를 맞추고, 내 저장소의 브랜치에서 작업한 뒤 Pull Request로 기여합니다.
Gitflow
main·develop을 기준으로 feature 브랜치에서 기능을 개발하고, release·hotfix 브랜치로 배포와 긴급 수정을 분리해 안정적인 이력을 유지합니다.
Stash
작업 도중 브랜치를 옮겨야 할 때 git stash push -m으로 메시지와 함께 임시 저장하고, stash list로 확인한 뒤 pop·apply로 복원합니다.
협업
feat·fix·refactor 같은 커밋 컨벤션으로 변경 의도를 드러내고, PR 코드 리뷰로 의견을 주고받습니다. 충돌이 나면 변경 내용을 팀원과 확인하며 merge·rebase로 해결합니다.
Harness Engineering
AI 코딩 에이전트가 프로젝트 맥락을 정확히 파악하도록 작업 환경을 설계합니다. 프로젝트 지침 문서(CLAUDE.md 등), 권한 설정, Hook, 재사용 가능한 Skill을 구성해 반복 작업을 자동화하고 결과물을 일관되게 유지합니다.
Coding Convention
네이밍, 파일 구조, 주석 스타일 같은 팀 컨벤션을 문서로 명시해 AI가 생성한 코드도 기존 코드와 같은 형태를 따르게 합니다. 생성된 코드는 리뷰와 린트로 다시 확인합니다.
Rules
작업 범위, 브랜치·커밋 규칙, 금지 사항 등 에이전트가 지켜야 할 규칙을 정해두고, 결과를 반드시 직접 검증한 뒤 반영합니다. AI를 도구로 쓰되 최종 판단과 책임은 개발자에게 있다는 원칙으로 작업합니다.
Semiconductor
